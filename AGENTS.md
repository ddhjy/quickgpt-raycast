# AGENTS.md

## Cursor Cloud specific instructions

QuickGPT is a **Raycast extension** (TypeScript + React). Standard commands live in
`package.json` scripts and `README.md`; only the non-obvious, cloud-relevant caveats are noted here.

### What can and cannot run on cloud (Linux, headless)
- The actual GUI runs **only inside the Raycast macOS desktop app**. `npm run dev` (`ray develop`)
  needs that app and **cannot run** on the Linux cloud VM. There is no way to launch the GUI here.
- These all work headlessly on Linux and are the way to validate changes:
  - `npm test` — Jest (`@raycast/api` is mocked via `src/tests/mocks/raycast-api.ts`).
  - `npm run lint` — `ray lint` (manifest validation + ESLint + Prettier). Also `npx eslint ./src/`.
  - `npm run build` — `ray build`; compiles both entry points and type-checks. Works on Linux.

### Type-checking requires a generated file
- `npx tsc --noEmit` fails with `Cannot find namespace 'Arguments'` on a fresh checkout because
  `raycast-env.d.ts` (git-ignored, defines the `Arguments.*` command-argument namespaces) does not
  exist yet. It is generated by `npm run build` (or `ray develop` on macOS).
- **Run `npm run build` once after installing deps** before relying on `tsc`/editor type-checking.

### Known date-dependent test failures (not a bug)
- `src/tests/prompt-usage-store.test.ts` hardcodes March 2026 dates and depends on the store's
  90-day retention window relative to the **current system clock**. Two tests
  ("prunes daily buckets older than 90 days on write", "accumulates multiple usages on the same day")
  fail once the system date is >90 days past those fixtures (i.e. mid-2026 onward). This is a test
  fixture/clock issue, not an environment or code problem. To see them green, run under a fake clock,
  e.g. `faketime '2026-03-20 12:00:00' npx jest prompt-usage-store`.

### Misc
- Node version is pinned by `.nvmrc` (22.14.0); the default cloud Node matches.
- `npm run fix-lint` (`ray lint --fix`) auto-fixes Prettier formatting.
